## Inputs still requiring real people/evidence

| Input | Required recorded information |
| --- | --- |
| Named author | Actual identity, domain competence and responsibility for original content; no synthetic account presented as a human |
| Independent subject reviewer | Actual qualified person distinct from original author/import operator, findings for the exact immutable version/hash, date and explicit disposition |
| Rights attestor | Actual accountable person/entity and underlying provenance/permission evidence; software validation is not an attestation |
| Lawful content | Original/licensed/otherwise authorized questions, passages and assets with traceable source version, spans/transformations, source status, intended uses, territory and validity period |
| Private answer material | Correct typed key, worked explanation, supporting evidence and scoring-policy version; do not place these in public screenshots, bundles or documentation |
| Equivalence decision | Exact version/hash, duplicate findings and human determination of distinct/repeated knowledge; automated fingerprint absence is insufficient |

Use actual source/evidence, never invented identities, signatures, reviewer
qualifications, permission or approval dates. A rights label alone is insufficient.
AI output still needs validation and the documented human process. No protected
question-bank scraping or unauthorized real-exam publication belongs in this workflow.

The starter target is **30 accepted items: Mathematics12, Reading6, Science12**.
Include the supported three interaction types and shared reading bundle with lawful
passage/assets. Count only accepted versions after the applicable human/rights/
equivalence gates; canonical counts and synthetic fixtures are not accepted stock.
The target alone does not guarantee two disjoint attempts: quota/bundle constraints
and NEW_ONLY history can reduce usable capacity. Report observed feasibility.

## Engineering workflow already available

1. Keep original content/provenance and private review materials in an authorized
   private intake location; do not commit secrets or unapproved real content.
2. Prepare immutable draft/reference graphs through the established Bank ingestion
   workflow. The local website's compact author form is a **synthetic MATH-only**
   demonstration, not a complete real Reading/Science content-management system.
3. In the disposable staff demo, managers can select displayed versions and run the
   explicit canonical preflight. Its shortfalls describe that selection. It does
   not evaluate current rights/accepted stock/human qualification or assembly
   feasibility, and it always retains the required human/rights blockers.
4. Match every human finding, rights record and equivalence decision to the exact
   version/hash. Changed versions need their applicable evidence; past receipts
   must not be substituted for current authorization or state.
5. Complete the established qualified review/publication process before introducing
   real material into student delivery. The current website provides no APPROVE,
   rights-edit or publication button. Do not bypass this through manual SQL or
   synthetic reviewer impersonation.

Managers can inspect current recorded rights text and bounded review history.
Those are unverified administrative records; arbitrary text may contain pasted
private information and is shown verbatim without a redaction guarantee. Keep it
private. UNKNOWN stays UNKNOWN. Recorded APPROVE is not platform attestation.
