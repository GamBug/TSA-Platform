## Observed acceptance gap

where opted in. Fixed forms are a separate explicit repeat-consented catalog choice.
A SHORTER_PROFILE alternative already exists in the frozen shortage DTO, but the
current server never advertises one. This is an honest unsupported alternative,
not a failure of the demonstrated three-domain journey.

one-section counts at MATH4/READING2/SCIENCE4. Directory validation and allocation

to bypass these boundaries.

## Proposed exact local scope

Add two explicit original synthetic short profiles: MATH2/180seconds and
SCIENCE2/180seconds. Preserve the existing MATH4/360, READING2/180 and SCIENCE4/360
fixture profiles. These durations are project practice settings, not official rules.
No shorter Reading profile: a two-member ALL_OR_NONE shared passage must not be
split to fabricate a one-question offer. Reading's current profile remains intact.

Short profiles remain one independent domain, PERSONALIZED_PRACTICE, strict
NEW_ONLY by default. No automatic review, shortened reservation, retry using a
new body, fixed form, combined-domain score or alternate reuse policy. An explicit
shorter choice identifies its own opaque blueprintVersionId/count/duration before
creation. It needs no repeat consent because it continues excluding all assigned
stable identities/current equivalence groups. Creating a shorter attempt is a new
logical request; retry of that request retains its own exact body/key.

The original MvpBlueprintConfigSchema and old immutable blueprints/vectors remain
unchanged. Introduce a separately named internal supported-profile guard/pin policy
for these two precisely bounded profiles, after owner disposition of expanded MVP
support. Do not silently widen the existing frozen schema or public root export.
Frozen student request/catalog/shortage shapes already model the proposed entries;
any actual need to alter those artifacts must be separately surfaced before coding.

Advertise a SHORTER_PROFILE only for an explicitly enabled current same-domain
short blueprint with correct configured count/duration. Its discovery is not a
promise of current stock or guaranteed feasibility: independent NEW_ONLY allocation
must still succeed or return its own truthful shortage. Do not run a second
allocation, write history, create forms, infer feasibility or call AI while merely
rendering an alternative. Inventory or rights can change between offer and click.

Shared capability defaultsfalse; initial implementation would enable only a new
explicit disposable synthetic launcher opt-in, with no retained/production activation
or new staff route/privilege. Personal catalog UI must render multiple profiles by
blueprintVersionId and domain, preserving current default4/2/4 selection. Merely
exhausting stock must never trigger a shorter POST. Existing REVIEW_ALLOWED and
fixed choices remain independently labeled and session-bound.
